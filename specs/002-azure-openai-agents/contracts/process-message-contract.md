# Contract: BaseAgent.ProcessMessageAsync

**Feature**: `002-azure-openai-agents`
**Date**: 2026-02-22
**Scope**: Public API contract for AI-powered agent message processing

## Overview

`ProcessMessageAsync` is the new primary entry point for agents to process user messages. It replaces the current pattern where callers pick a tool by name and call `ExecuteToolAsync` directly. This method integrates the LLM for intent understanding, tool selection, multi-tool chaining, and natural-language response generation.

## Method Signature

```
public async Task<string> ProcessMessageAsync(
    string userMessage,
    IReadOnlyList<SessionMessage> conversationHistory,
    IProgress<ProgressUpdate>? progress = null,
    CancellationToken cancellationToken = default)
```

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `userMessage` | `string` | Yes | The user's current message text |
| `conversationHistory` | `IReadOnlyList<SessionMessage>` | Yes | Prior messages in the conversation session (may be empty for first message) |
| `progress` | `IProgress<ProgressUpdate>?` | No | Callback for streaming tokens and progress updates to the caller |
| `cancellationToken` | `CancellationToken` | No | Cancellation token for the request |

### Return Value

- **Type**: `Task<string>`
- **AI-enabled mode**: Natural-language response generated by the LLM after tool execution
- **Fallback mode**: Raw JSON from direct first-tool execution (current behavior)
- **Max rounds exceeded**: Explanatory message indicating the request was too complex

### Exceptions

| Exception | Condition |
|-----------|-----------|
| `ArgumentNullException` | `userMessage` is null |
| `OperationCanceledException` | `cancellationToken` is cancelled |
| Propagated tool exceptions | If a tool throws during execution (both AI and fallback modes) |

## Behavioral Contract

### Mode Selection (checked at entry)

```
IF _chatClient is null OR AgentAIEnabled is false:
    → Fallback mode
ELSE:
    → AI-enabled mode
```

### AI-Enabled Mode

1. **Build chat messages**:
   - `ChatRole.System`: Agent's system prompt from `GetSystemPrompt()`
   - `ChatRole.User` / `ChatRole.Assistant`: Converted from `conversationHistory` (map `SessionMessage.Role` → `ChatRole`)
   - `ChatRole.User`: Current `userMessage`

2. **Build tool definitions**:
   - For each registered `BaseTool` → create `AIFunction` with:
     - Name = `tool.Name`
     - Description = `tool.Description`
     - Parameters derived from `tool.Parameters` JSON Schema
     - Invocation delegate wrapping `ExecuteToolAsync`

3. **Configure chat options**:
   - `Tools` = list of `AITool` from step 2
   - `Temperature` = configured temperature (default 0.3f)

4. **Call LLM via streaming**:
   - `_chatClient.GetStreamingResponseAsync(messages, options, cancellationToken)`
   - The `FunctionInvokingChatClient` middleware handles tool-call rounds automatically
   - Max rounds enforced via `FunctionInvokingChatClient.MaximumIterationsPerRequest`

5. **Stream tokens**:
   - Each text `ChatResponseUpdate` → `progress?.Report(new ProgressUpdate { Message = update.Text })`
   - Accumulate full response text

6. **Return**: Complete response text

### Fallback Mode (no AI)

1. Get first tool from registered tools: `Tools.FirstOrDefault()`
2. If tool exists: call `ExecuteToolAsync(tool.Name, new Dictionary<string, object?>(), progress, cancellationToken)`
3. Return tool result string (raw JSON)
4. If no tools registered: return explanatory message

### Error Handling

| Scenario | Behavior |
|----------|----------|
| LLM API call fails (network/auth) | Log error; fall back to direct tool execution |
| Hallucinated tool name from LLM | `FunctionInvokingChatClient` handles — function not found → error sent back to LLM for recovery |
| Tool execution throws | Exception propagated as `FunctionResultContent` error → LLM explains to user |
| Max rounds exceeded | `FunctionInvokingChatClient` stops; returns partial response or explanation |
| Empty LLM response | Return empty string; caller handles |
| Cancellation requested | Throw `OperationCanceledException` |

## Progress Reporting Contract

The `IProgress<ProgressUpdate>` callback receives updates during processing:

| Phase | ProgressUpdate.Message | ProgressUpdate.PercentComplete | ProgressUpdate.Data |
|-------|------------------------|-------------------------------|---------------------|
| LLM thinking | "Processing your request..." | null | null |
| Tool executing | "Running {toolName}..." | null | `{ toolName }` |
| Streaming token | (partial response text) | null | null |
| Complete | (final response text or empty) | 100 | null |

## Caller Integration (ChatHub)

```
// Before (current):
var toolResult = await agent.ExecuteToolAsync(
    agent.GetToolMetadata().First().Name,
    new Dictionary<string, object?>(),
    progress);

// After:
var response = await agent.ProcessMessageAsync(
    message.Content,
    session.Messages,
    progress,
    cancellationToken);
```

The ChatHub stores `response` (not raw tool JSON) in `SessionMessage.Content` for the assistant message.

# Contract: AzureOpenAIChatClientFactory

**Scope**: Factory service for constructing the `IChatClient` from configuration

## Method Signature

```
public IChatClient? CreateChatClient()
```

### Return Value

- **Non-null**: When `AzureOpenAI:Endpoint` is configured with a valid URI
- **Null**: When endpoint is empty, missing, or configuration section is absent

### Behavior

| Config State | Auth Method | Azure Cloud | Result |
|-------------|-------------|-------------|--------|
| Endpoint empty | — | — | Returns null |
| Endpoint set, ApiKey set | `ApiKeyCredential` | Detected from URI | `IChatClient` |
| Endpoint set, ApiKey empty | `DefaultAzureCredential` | Detected from URI | `IChatClient` |
| Endpoint contains `.us` | (either) | `AzureGovernment` | `IChatClient` with Gov audience |
| Endpoint does not contain `.us` | (either) | `AzureCloud` (default) | `IChatClient` |

### DI Registration

Registered as a singleton in both MCP and Chat `Program.cs`:
```
services.Configure<AzureOpenAIOptions>(config.GetSection("AzureOpenAI"));
services.AddSingleton<AzureOpenAIChatClientFactory>();
services.AddSingleton<IChatClient?>(sp => sp.GetRequiredService<AzureOpenAIChatClientFactory>().CreateChatClient());
```

# Contract: Enhanced System Prompts

**Scope**: Additive sections for each agent's `.prompt.txt` file

Each of the 9 `.prompt.txt` files receives two new sections appended after existing content:

### Section: Response Guidelines

```
## Response Guidelines

- Format responses using Markdown: tables, code blocks, bullet lists
- Use severity badges: [CRITICAL], [HIGH], [MEDIUM], [LOW], [INFO]
- Include actionable next steps when findings are reported
- Summarize complex data rather than dumping raw JSON
- Use tables for structured comparisons (e.g., resource lists, cost breakdowns)
- Keep responses concise but comprehensive — aim for the right level of detail
```

### Section: Tool Selection

```
## Tool Selection

- Select tools based on user intent, not keyword matching
- For compound requests, chain tools in logical order (e.g., assess → plan)
- When the user's intent is ambiguous, ask one clarifying question before acting
- If a tool fails, explain the error and suggest alternatives
- Never call a tool without sufficient parameters — ask the user if required params are missing
- Available tools: [dynamically listed from agent's registered tools]
```

**Contract**: Existing prompt content above these sections MUST NOT be modified.
